## プロトタイプの範囲

1アカウントを1画面で確認するもの。サマリー、日次推移、投稿別の比較、1時間ごとの取得を含む。ログイン、チーム、クライアント管理、DBは含まない。

## 第1層：戦略（確定）

- **対象:** フリーランスのSNS運用者、自社アカウントを持つ企業
- **利用形態:** 管理者が、担当する複数のアカウントの数値を一覧で確認する（B：管理型）。チームでも利用できる
- **媒体:** 初回はInstagram。次にYouTube、TikTokへ広げられる形にする
- **将来の方向:** 取得した数値をもとに、運用に合った投稿管理とKPI作成ができるようにする
- **解決する課題:** 媒体ごとの確認や記録に手間がかかり、横断での比較や履歴の保存が難しい
- **目的:** アカウントを一度接続すれば、各媒体の数値が自動で集まり、確認できること
- **成功の指標:** 確認や転記の手間の削減、接続完了率、自動取得の成功率
- **やらないこと:** パスワードの保管や独自のログイン認証の開発。初回は投稿管理とKPI作成も行わない
- **ログイン方針:** Googleログインのみ。認証処理は外部の認証サービスに任せる
- **自社の責任として残るもの:** ユーザー間のデータ分離、SNS接続用トークンの安全な管理、退会時のデータ削除

## 第2層：要件（案）

### 用語

- **チーム:** データと権限を管理する単位。フリーランスは1人のチームとして使う
- **メンバー:** チームに所属し、Googleでログインして数値を確認する人。権限はオーナーとメンバーの2種類
- **クライアント:** チームが担当する単位。企業が自社利用する場合はブランドや部署を登録する

### 初回リリース

| ID | 機能 | 内容 |
|---|---|---|
| F1 | ログイン | Googleログイン。所属チームのクライアントだけを閲覧できる |
| F2 | チーム管理 | 招待リンクでメンバーを追加、削除する。チーム管理、接続、削除の操作はオーナーのみ |
| F2b | クライアント管理 | 追加、編集、削除 |
| F3 | 媒体接続 | Instagramの公式画面で許可する。接続状態を表示する |
| F4 | 自動取得 | 公式API経由で1時間に1回取得して履歴を蓄積する。失敗を検知して表示する |
| F5 | 一覧 | クライアントと媒体ごとの主要指標、前期間比、接続の異常を表示する |
| F6 | 詳細 | 媒体別の推移と投稿別の数値を表示する |
| F7 | データ削除 | クライアント削除と退会時に、接続情報と取得データを削除する |

### 取得する指標（Instagram・技術検証で確定）

- **アカウント:** フォロワー数、リーチ、閲覧数、いいね、コメント、保存、シェア
- **投稿:** リーチ、閲覧数、いいね、コメント、保存、シェア
- **リール:** 平均視聴時間、3秒離脱率

### コンテンツ要件

- 媒体ごとに定義が異なる指標は、同じ名前でも合算せず別々に表示する
- 「データなし」「実測値の0」「取得失敗」を区別して表示する
- 取得できない指標は理由を示す（例：フォロワー100人未満で提供されないデータ）
- 日時は日本時間で表示する

### 初回は作らないもの

クライアントごとの閲覧権限、クライアント向け閲覧画面、PDFレポート、次の一手の提案、ルールチェック、スマホ専用の最適化、課金機能。

### データ取得の方針

- 第一候補はInstagram公式API。`scripts/verify-instagram-api.mjs` で実アカウントを検証して決める
- **採用条件:** 必要な指標を取得でき、1時間ごとの取得が呼び出し上限に当たらないこと
- **不採用の場合:** Windsor.aiで自分とチームの利用向けに進める。1時間ごとの更新にはStandard以上が必要（2026-10-30時点）で、他のユーザーへの提供には書面許可が必要
- 取得処理は画面と分離し、取得元を差し替えられる形にする

### 公開前に必要なもの

- MetaのApp ReviewとAdvanced Access（YouTube、TikTok対応時は各社の審査や確認も必要）
- Meta Platform Termsとブランドガイドラインの確認。アプリ名にInstagram等の商標を含めない
- プライバシーポリシーと利用規約
